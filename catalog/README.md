# catalog/: how each claim is checked, and at which level

The specs (`specs/`, `docs/specs.md`) say **what** is claimed: a specification (observable ×
domain × aggregate), as `ClaimType` terms with their `Sound` theorem, proved once
(`formal/core/Specs/ClaimTypes.lean`). The catalog says **how** it is checked.
Each fact is written in one place:

```
claim card    specs/claims/X.md        claim_types = [ClaimType terms]: Spec, check, Sound theorem
  ↑ establishes
method        catalog/methods/Y.toml   the check the kernel runs (lean.check, checks), and
                                       lean.correctness: an accepted check ⇒ the acceptance of Sound
  ↑ feeds
method        catalog/methods/Z.toml   computes an input Y checks (e.g. the kernel's error count)

guarantee     catalog/guarantees/G.toml   what a certificate names: one claim + the methods it uses
```

| Field | Meaning |
| --- | --- |
| `establishes` | the claims whose `Sound` theorem this method's accepted check satisfies |
| `feeds` | the methods that consume what this method computes |
| `checks` | its fast checks in `formal/core/Checks/Registry.lean` (`ot_kernel`, `ot_check`) |
| `lean.spec` | the definitions its statements mention |
| `lean.check` | the definition the kernel evaluates on each certificate |
| `lean.correctness` | the kernel-checked theorems from an accepted check to the claim's acceptance condition |
| `assumptions` | the ids of `specs/assumptions/` its result depends on |

**Levels are derived, not declared** (`tests/regression/registry.py`, levels as in
[specs/protocols/assurance-levels.md](../specs/protocols/assurance-levels.md)). A method is
**verified** exactly when it has a mode, `lean.spec`, `lean.correctness` and a conformance test, and
establishes claims that all have a `Sound` theorem (or feeds a method). It is **specified** when it has
`lean.spec` and states `not_verified_because`, and **experimental** otherwise. CI fails when the
declared level differs from the derived one. A guarantee's level is that of its weakest method,
and it lists every assumption of its claim and its methods. `contracts/` (compositions of
guarantees between parties) is empty.

The tables below are generated by `python3 tests/regression/check_catalog.py --write`.
